# AX5689 input bridge — ASRC на Gowin GW5A (Tang Primer 25K)

Форк идеи [ppy2/gowin-dsd-pcm-bridge](https://github.com/ppy2/gowin-dsd-pcm-bridge)
для усилителя DigiD D1: коммутатор на **5 входов** (Fox с PCM 44.1…768 кГц,
DSD64…512, DoP; **встроенный приёмник S/PDIF** на четыре линии — коаксиал,
оптика, AES/EBU, HDMI ARC — вместо AK4118A; I2S-вход PCM для Bluetooth; вход
HDMI с PCM, DoP и нативным DSD и вход модуля фонокорректора с АЦП AK5572,
каждый со своим клоком), выход — **I2S 192 кГц / 32 бит**, тактируемый
**собственным генератором 49.152 МГц** усилителя. Управление и статус —
по I2C с STM32. Клок транспорта до выхода не доходит: он только
вдвигает данные, дальше работает настоящий асинхронный SRC с цифровым PLL.

Связь с прошивкой усилителя (STM32H523, [DigiD-D2](https://github.com/DrModd/DigiD-D2)) и
стримером ([DigiFox2](https://github.com/DrModd/DigiFox2)) — договор в
[`INTERFACES.md` репозитория DigiD-D2](https://github.com/DrModd/DigiD-D2/blob/main/INTERFACES.md):
сигналы, регистры I2C, загрузка эквалайзера. При изменении регистров правится и он.
Драйвер хоста для эквалайзера — `Core/Src/ax_eq.c` там же.

RTL написан заново (сохранена только раскладка пинов и измеренная ppy2
перестановка L/R в DSD-режиме PureFox).

```
 вход 0: Fox (PCM/DoP/DSD)   входы 1–3: I2S PCM     генератор 49.152 МГц
        └──────────┬──────────────┘                   │ (он же MCLK AX5689)
               [in_mux] ◄── выбор по I2C (STM32)       ▼
   [bclk_rx] ─ async FIFO ─► rate_mon, DoP ───────────────────────────────
   (домен BCLK)               │                                            │
   PCM 44.1/48   ─► ×2 hb_a ─► ×2 hb_b ─┐                                  │
   PCM 88.2/96   ─────────────► ×2 hb_b ─┤                                 │
   PCM 176.4/192 ────────────────────────┼─► ASRC + DPLL ─► fade ─► EQ ─► I2S TX ─► AX5689
   PCM 352.8/384 ─────────────► ÷2 hd_b ─┤   (→192 кГц)    10 биквадов/канал   192k/32
   PCM 705.6/768 ─► ÷2 hd_a ─► ÷2 hd_b ─┤
   DSD64…512, DoP64…256 ─► CIC5 ─► ÷2 dsd┘
```

## Форматы

| Вход | Обработка до ASRC | Промежуточная частота |
|---|---|---|
| PCM 44.1 / 48 | интерполяция ×4 (два полуполосных КИХ) | 176.4 / 192 |
| PCM 88.2 / 96 | интерполяция ×2 | 176.4 / 192 |
| PCM 176.4 / 192 | — | 176.4 / 192 |
| PCM 352.8 / 384 | децимация ÷2 (полуполосный) | 176.4 / 192 |
| PCM 705.6 / 768 | децимация ÷4 (два полуполосных) | 176.4 / 192 |
| DSD64…DSD512 (нативный, Amanero) | CIC 5-го порядка ÷8…64 → КИХ ÷2 с компенсацией | 176.4 |
| DoP64…DoP256 | то же | 176.4 |

Частота и формат определяются автоматически (подсчёт слов за окно 5.3 мс
по своему клоку, детектор маркеров DoP 0x05/0xFA, вывод DSD_ON).

Выход: I2S Philips, мастер, 32-битные слоты, 192 кГц. BCLK = 12.288 МГц
(MCLK/4), LRCK = MCLK/256. Данные 32 бита: 24 бита входа плюс дробные
биты фильтра ASRC.

| Ступень | Длина | Полоса пропускания | Подавление |

| hb_b ×2 (88.2→176.4) | 91 | 0–36 кГц | −120 дБ от 52.2 кГц |
| hd_a ÷2 (705.6→352.8) | 23 | 0–40 кГц | −120 дБ |
| hd_b ÷2 (352.8→176.4) | 31 | 0–40 кГц | −119 дБ |
| CIC5 (DSD) | — | спад −0.33 дБ на 24 кГц (компенсируется) | > 120 дБ вокруг кратных 352.8 кГц |

выше 40 кГц это потеря (осознанная).

## Цифровой PLL

Опорные события — раз в 4 промежуточных отсчёта (44.1 / 48 кГц), метка
времени с точностью до такта 49.152 МГц. Петля 3-го порядка (ПИ + ФНЧ
ошибки), ступенчатое сужение полосы: ~200 Гц → 25 Гц → 3 Гц → 0.6 Гц →
0.3 Гц. Звук включается после второй ступени (~0.3 с после появления
потока), дальше полоса сужается уже на ходу без скачков фазы.

Модель (tools/dpll_model.py): остаточный джиттер даёт шум ниже −129 дБ на
15 кГц (отстройка > 10 Гц от несущей) при разбеге кварцев Fox и усилителя
от 3 ppm. Известное ограничение: если генераторы совпадают точнее ~1 ppm
(семейство 48 кГц), квантование меток на 20 нс даёт медленную модуляцию
фазы, до −104 дБ на 15 кГц. Лечится метками от PLL ×4 (см. «Дальше»).

Бенч коммутатора (tb_mux.v): одновременно работают вход 0 — DSD64

Бенч запаса уровня (`--clip`): синус fs/4 под 45°, отсчёты ровно на
полной шкале, истинный пик +3 dBFS. Без запаса фильтры насыщаются: флаг
CLIP поднят, THD+N −60.8 дБ. С запасом 3.5 дБ: флага нет, уровень ровно
−0.49 dBFS (= +3.01 − 3.50), THD+N −136.4 дБ.

Бенч восстановления (`make recover`, tb_recover.v): во время
воспроизведения принудительно взводится флаг переполнения ступени — мост
глушит звук и сам захватывает поток заново (~18 мс). Монитор на каждом
переключении мультиплексора входов проверяет, что сброс приёмника уже
действует не меньше 64 тактов; повторный запрос внутри окна сброса
приводит к последнему выбранному входу.

Бенч переключений (tb_switch.v): 44.1 → пауза → 96 → DSD64 → пауза →
768 → DoP64 → 192. Звук гаснет в момент смены формата (за < 0.01 мс),
мост захватывает новый формат с правильным трактом, пиковое значение на
выходе ни разу не превысило уровень программы (щелчков и мусора нет).

Эквалайзер (`make eq`, `make eqsys`): RTL совпадает с моделью бит-в-бит
на 2000 кадрах, включая смену банка 10 → 4 секции на живых состояниях и
412 насыщений; занятость 181 такт из 256. Системный бенч (tb_eqsys.v):
PCM 96 кГц, коэффициенты загружены по I2C одной передачей во время
захвата, apply, затем обход «на ходу». L (−6 дБ на 1 кГц + полка +3 дБ
на 100 Гц): −6.99 dBFS при расчётных −6.99, THD+N −131.9 дБ; R (−3.5 дБ на
7 кГц + ВЧ-фильтр 20 Гц): −4.50 / −4.50, −134.3 дБ. После обхода — ровно
−1.00 dBFS, −138.8 / −137.6 дБ, без пропадания звука.

## Коммутатор входов и I2C

Обрабатывается только выбранный вход: перед приёмником стоит
мультиплексор BCLK/LRCK/DATA. Смена входа = смена формата: мгновенный
фейд, затем приёмник и FIFO уходят в сброс, и только через ~21 мкс
(1024 такта) под действующим сбросом переключается мультиплексор; ещё
через ~21 мкс сброс снимается (глитч переключаемого клока безвреден),
затем захват нового потока, звук через ~0.3 с. Вход 0
(Fox) понимает нативный DSD по DSD_ON, DoP распознаётся на любом входе.

I2C-слейв, адрес **0x5A** (параметр `I2C_ADDR` в top.v), 100/400 кГц,
указатель регистра с автоинкрементом:
запись `S 0xB4 reg data… P`, чтение `S 0xB4 reg Sr 0xB5 data… P`.

| Рег. | | Содержимое |
|---|---|---|
| 0x00 CTRL | RW | [2:0] вход 0…4 (5…7 → 4), [7] mute (держит тишину, захват не начинается) |
| 0x01 STATUS | R | [0] звук идёт, [1] захват/работа, [3:2] текущий вход (младшие биты), [7:4] входы 0…3 с живым LRCK (как в VERSION ≤ 0x05) |
| 0x02 FORMAT | R | [2:0] k (частота = 44.1/48 × 2^k для PCM), [3] семейство 48 кГц, [4] нативный DSD, [5] DoP, [7] валидно |
| 0x03 RATE | R | 0 — нет; PCM 1…10 = 44.1, 48, 88.2, 96, 176.4, 192, 352.8, 384, 705.6, 768; 0x11…0x14 = DSD64…512; 0x21…0x23 = DoP64…256 (+0x08 для DSD семейства 48 кГц) |
| 0x04 PLL | R | ступень цифрового PLL (0…4) |
| 0x05 ID | R | 0xA5 |
| 0x06 VERSION | R | 0x08 (выводы платы D2, левый канал DSD Фокса на своей линии) |
| 0x07 ATT | RW | [3:0] запас уровня для PCM: 0…12 × 0.5 дБ (0…6 дБ), по умолчанию `ATT_DEFAULT` |
| 0x08 CLIP | R / W | чтение: [0] насыщение в тракте за последние ~85 мс, [7] было с момента сброса флага; запись любого значения сбрасывает [7] |
| 0x09 EQ_CTRL | R / W | чтение: [0] apply ждёт кадра, [1] активный банк, [7:4] активное число секций; запись [0] = 1 — применить |
| 0x0A EQ_NSEC | RW | число секций на канал для следующего apply, 0…10 (0 — обход бит-в-бит, по умолчанию) |
| 0x0B EQ_IDX | RW | индекс слова коэффициента 0…99; запись сбрасывает счётчик байтов |
| 0x0C EQ_DATA | W | байты коэффициентов, старший первым, по 4 на слово, в **неактивный** банк; индекс растёт сам, указатель I2C на 0x0C не двигается |
| 0x0D DSD_MODE | RW | по 2 бита на вход (вход 0 — [1:0] … вход 3 — [7:6]): бит 0 — флаг DSD с пина (у входа 0 `dsd_on`, у входа 3 `in3_dsd`), бит 1 — автоопределение DSD; после сброса 0xC1 (Fox — флаг, HDMI — флаг и автоопределение) |
| 0x0E DSD_CFG | RW | [3:0] по входам: 1 — правый канал DSD на SDATA, 0 — на LRCK; [7:4] флаг DSD активен низким; после сброса 0x0F (бит 0 = `DSD_SDATA_IS_RIGHT`) |
| 0x0F INPUTS | R | [4:0] входы 0…4 с живым LRCK (вход 1 — S/PDIF захвачен), [7:5] текущий вход 0…4 |
| 0x10 SPDIF_SEL | RW | [1:0] линия S/PDIF: 0 коаксиал, 1 оптика, 2 AES/EBU, 3 ARC; смена — как смена входа |
| 0x11 SPDIF_STAT | R/W | [0] захват, [1] не звук (channel status или пакеты IEC 61937, Dolby/DTS — не играет), [2] ошибки за ~85 мс, [7] ошибки с последней записи (запись сбрасывает) |
| 0x12 SPDIF_CS0 | R | байт 0 channel status |
| 0x13 SPDIF_CS3 | R | байт 3 channel status (код частоты у бытового формата) |

Проверьте, что адрес 0x5A не занят на шине (AX5689 и прочее).

**Запас уровня и клиппинг.** «Громкие» мастеринги часто содержат
межвыборочные пики выше 0 dBFS: сами отсчёты в пределах шкалы, а
восстановленный сигнал — нет. Интерполирующие фильтры и ASRC такие пики
честно вычисляют и упираются в насыщение. ATT (0…6 дБ, шаг 0.5 дБ) ставит
ослабление перед всеми фильтрами PCM-тракта; при 0 дБ путь бит-в-бит
прежний. DSD не ослабляется: его 0 дБ SACD и так −6 dBFS. Громкость
по-прежнему на AX5689, поэтому 1–2 дБ запаса ничего не стоят. Флаг CLIP
показывает, что насыщение всё-таки случилось — удобно для индикатора на
дисплее.

## Выводы платы D2 (gowin/ax_bridge_d2.cst)

Раскладку задаёт плата DigiD D2 (схема NAXF, 13.11.2026). Файл `gowin/ax_bridge_d2.cst`
**один на ax-bridge и ax-bridge2, одинаковый байт в байт**: обе прошивки проверяются на
одной плате. Менять только вместе с платой и копировать в оба репозитория. Прежние
`ax_bridge.cst` и `ax_bridge_j2.cst` удалены. Все выводы есть и на Dock (схема
Tang_25K_60033).

| Сигнал | Вывод | |
|---|---|---|
| mclk_in | F2 (J2-7, GCLKT_9B) | генератор 49.152 МГц, общий с AX5689 |
| sys_clk | E2 | генератор 50 МГц модуля; здесь не используется, порт есть ради общего файла выводов (его использует ax-bridge2) |
| i2s_bclk_in | H5 | вход 0, Фокс, вывод 24: BCLK / такт DSD |
| i2s_lrck_in | D11 | Фокс, вывод 25: LRCK |
| i2s_sdata_in | B11 | Фокс, вывод 29: данные PCM / правый канал DSD |
| i2s_dsdl_in | **E10** (J1-54) | Фокс, вывод 27 (I2S_SDO1): **левый канал DSD**, через 33 Ом |
| dsd_on | G11 | Фокс, вывод 19: флаг нативного DSD |
| spdif_in[0..2] | C10 / D10 / B10 | коаксиал / оптика / AES (каскады на основной плате) |
| spdif_in[3] | F5 | HDMI ARC (с модуля входов) |
| in2_bclk / in2_lrck / in2_sdata | J8 / G10 / L11 | вход 2: Bluetooth |
| in3_bclk / in3_lrck / in3_sdata | F7 / G5 / G7 | вход 3: HDMI I2S. Флага DSD на плате нет: `in3_dsd` = 0 внутри, DSD определяется автоматически (DSD_MODE бит 7, включён после сброса) |
| in4_bclk / in4_lrck / in4_sdata | J11 / J10 / L10 | вход 4: фонокорректор (AK5572) |
| i2c_scl / i2c_sda | G8 / H8 | I2C к STM32 (подтяжки на плате) |
| i2s_bclk_out / i2s_lrck_out / i2s_sdata_out | L2 / L1 / K1 (J2-6 / 8 / 10) | → AX5689 |
| audio_on | A10 | → STM32 PD2, 1 = звук идёт |

Банк 2 (L2, L1, K1) питается снаружи: VCCIO2/3 на J2-2 / J2-4 = 3.3 В.

Выбранный BCLK мультиплексируется в логике и выводится на глобальную
сеть, поэтому входным BCLK тактовые пины не обязательны. Параметр
`USE_DCS=1` включает вместо этого штатный переключатель клоков Gowin
(DCS) — сверьте имя и порты примитива с документацией вашей версии IDE.

**Левый канал DSD Фокса.** Фокс в нативном DSD отдаёт левый канал на выводе 27
(I2S_SDO1), а не на LRCK. Параметр `FOX_DSDL` в top.v: **1** (по умолчанию) — при
`dsd_on` = 1 левый канал берётся с `i2s_dsdl_in`; **0** — старая трёхпроводная раскладка
Amanero (левый канал на LRCK). PCM и DoP всегда идут по LRCK. Перестановка каналов
(0x0E) работает как раньше: «LRCK» в ней — линия левого канала.

**Порты для стендов.** Без макроса `AXB_SIM_PORTS` `top` собирается ровно с выводами
D2. Стенды начинаются с `` `define AXB_SIM_PORTS `` — тогда у `top` есть `in3_dsd`
(проверка флага DSD на HDMI). Gowin макрос не видит.

DSD L/R для Fox после сброса: параметр `DSD_SDATA_IS_RIGHT` в top.v
(1 = правый канал на SDATA, как ppy2 измерил у PureFox); дальше порядок
каналов любого входа меняется по I2C (0x0E).

## Вход 1: приёмник S/PDIF (`rtl/spdif_rx.v`)

Вместо AK4118A: четыре линии S/PDIF / AES3 (коаксиал, оптика, AES/EBU, HDMI
ARC) приходят логическим уровнем, декодируется выбранная (регистр 0x10).
Всё на MCLK: линия читается по обоим фронтам 49.152 МГц (98 Мвыб/с), на
192 кГц это 4 выборки на полуячейку бифазного кода. Длины импульсов
классифицируются по самому длинному импульсу преамбулы (3T) — отдельно для
высокого и низкого уровня, поэтому перекос скважности оптических приёмников
вычитается: на 192 кГц без ошибок ±15 нс перекоса плюс 4 нс дрожания,
44.1–96 кГц — с большим запасом (tb/run_sys.py --spdif, проверка по
выходу: THD+N, уровень, частота). Кадры (24 бит) идут сразу в общий тракт
после FIFO — у входа 1 нет своего клока, ASRC подстраивается под поток.
Захват — 16 хороших кадров подряд, кадр с ошибкой чётности или кода (и
кадр без левого подкадра) повторяет предыдущий (частота для ASRC не
меняется). 32 кГц не поддерживается, как и на остальных входах.

Сжатый звук (Dolby / DTS) не выходит никогда, даже на мгновение:
- после захвата ни одного отсчёта, пока не прочитан целый блок channel
  status (192 кадра, 1–4 мс): до этого неизвестно, PCM ли это;
- бит 1 байта 0 channel status = 1 → тишина;
- преамбула пакета IEC 61937 (Pa/Pb = 0xF872 / 0x4E1F в старших 16 битах
  кадра) → тишина сразу и ещё ~170 мс после последней: плеер, переходящий
  с PCM на Dolby, меняет бит channel status только со следующего блока, а
  некоторые источники не ставят его вовсе. Раньше в этот момент (и первые
  кадры после переключения на такой вход) шёл громкий цифровой шум.

Если источник меняет частоту без паузы в линии (смена трека), сетка
длительностей становится чужой. Небольшой шаг (44.1 ↔ 48, 88.2 ↔ 96,
176.4 ↔ 192) ловится на первом же подкадре: его длина отличается от 64T
больше чем на 3 %. Большой (×2, ×4) — через ~330 мкс без единого чистого
подкадра. В обоих случаях приёмник сбрасывает сетку, теряет захват, заново
подстраивается и читает channel status, так что полуподходящая сетка не
успевает пропустить подкадры с чётным числом ошибочных битов (раньше после
×2 / ×4 вход мог остаться без звука до переключения). Проверка —
`make spdif_stress`: шаги частоты на ходу с перекосом скважности, 42 переключения линий в случайные моменты, смены
частоты 32–192 кГц на ходу (с паузой и без), пакеты IEC 61937 при PCM в
channel status, вход не-PCM с самого начала; в данных счётчик кадров
(L = n, R = ~n), так что любой испорченный отсчёт на выходе виден.

## Вход HDMI: нативный DSD

Приёмники HDMI (экстракторы I2S/DSD для SACD с Oppo, PS3 и т. п.) отдают
DSD по тем же трём линиям: BCLK = DSD-клок (2.8224 МГц для DSD64), два
битовых потока на LRCK и DATA. Признак DSD у разных плат свой, поэтому
вход 3 понимает DSD двумя способами (оба включены после сброса):

- **флаг** — пин `in3_dsd`, полярность выбирается (0x0E [7]);
- **автоопределение** — без флага, по самому сигналу: в I2S PCM линия
  LRCK меняется раз в слот, то есть не чаще, чем раз в 16 тактов BCLK, а в
  DSD на ней поток данных с короткими сериями. 16 перепадов ближе 8 тактов
  из 64 → DSD; 128 перепадов подряд не ближе 16 тактов → снова PCM. На
  обычном PCM ложных срабатываний не бывает (у PCM интервал ≥ 16 по
  построению), включение — за десятки микросекунд, дальше обычный захват.

Порядок каналов (на какой линии левый) тоже бывает разный — 0x0E [3:0].
Если звук DSD с HDMI идёт с перепутанными каналами, достаточно записать
0x0E = 0x07. Автоопределение можно включить и на любом другом входе
(0x0D), а DoP распознаётся везде, как и раньше. Формат и частота видны в
FORMAT/RATE, как для Fox.

## Эквалайзер / рум-коррекция

После ASRC и фейда, на фиксированной частоте 192 кГц, стоят до **10
биквадов на канал** (L и R независимо), `rtl/eq_biquad.v`. Один общий
умножитель 32×32, кадр обрабатывается за 181 такт из 256, коэффициенты
в одном блоке BSRAM (два банка), задержка +1 отсчёт (5 мкс).

- Секция Direct Form I: `y = b0·x + b1·x1 + b2·x2 − a1·y1 − a2·y2`.
  Данные 32 бит, коэффициенты 32 бит Q3.29 (2^29 = 1.0, диапазон ±4),
  сумма 67 бит.
- Шум округления не накапливается: остаток квантования возвращается
  через (2z⁻¹ − z⁻²) (error feedback 2-го порядка), поэтому даже узкие
  секции на 20–40 Гц при 192 кГц не шумят. Погрешность фиксированной
  точки относительно float64 — **−191 dBFS** (полоса 20 Гц – 20 кГц) на
  тестовом наборе из 10 «злых» секций (ВЧ-фильтр 15 Гц, +6 дБ на 20 Гц,
  −12 дБ Q8 на 38 Гц, полки и т. д.).
- Квантование коэффициентов Q3.29: АЧХ отличается от расчётной не
  больше чем на 0.09 дБ выше 15 Гц (худший случай — вырез −10 дБ с Q10 на
  42 Гц). ВЧ-фильтр на 10 Гц расходится на 0.15 дБ на самих 10 Гц.
- Ограничение диапазона ±4: высокочастотная полка с подъёмом больше
  ~+7 дБ не помещается (`eq_coefs.py` об этом скажет) — разбейте её на две
  секции. Для рум-коррекции (в основном вырезы) это не мешает.
- Каждая секция насыщается до S32 и поднимает флаг CLIP. Подъёмы
  компенсируйте запасом: ATT (0x07) для PCM или отрицательным усилением
  в одной из секций.
- Фейд стоит **до** эквалайзера: начало и конец потока входят в фильтры
  плавно, ВЧ-фильтр на 20 Гц не «звенит» на старте.

**Загрузка.** Хост пишет весь набор в неактивный банк и делает apply:
банки меняются на границе кадра, число секций меняется одновременно —
щелчков от полузаписанного набора не бывает. После apply запись идёт в
другой (старый) банк, поэтому при каждом обновлении загружается весь
набор (100 слов = 400 байт, ~10 мс на 400 кГц). Секции с номером ≥ nsec —
точная единица, их коэффициенты не важны.

Слово с индексом `sec·10 + ch·5 + k`: ch 0 = L, 1 = R; k = b0, b1, b2,
a1, a2 (a0 = 1, знак a — как в формуле выше, как у scipy/RBJ). В экспорте
REW в формате miniDSP a1/a2 идут с обратным знаком — для него `--rew-negated`;
проверить легко: скрипт печатает итоговую АЧХ, она должна совпасть с REW.

```c
/* STM32 HAL, адрес 0x5A; coef[] из tools/eq_coefs.py --c */
static void ax_eq_load(const int32_t *coef, uint8_t nsec)
{
    static uint8_t buf[400];
    uint8_t v;
    for (int i = 0; i < nsec * 10; i++) {          /* слова 0 .. nsec*10-1 */
        uint32_t u = (uint32_t)coef[i];
        buf[4*i] = u >> 24; buf[4*i+1] = u >> 16; buf[4*i+2] = u >> 8; buf[4*i+3] = u;
    }
    do {                                           /* прошлый apply должен пройти */
        HAL_I2C_Mem_Read(&hi2c1, 0x5A << 1, 0x09, 1, &v, 1, 10);
    } while (v & 1);
    v = 0;     HAL_I2C_Mem_Write(&hi2c1, 0x5A << 1, 0x0B, 1, &v, 1, 10);
    HAL_I2C_Mem_Write(&hi2c1, 0x5A << 1, 0x0C, 1, buf, nsec * 40, 100);
    v = nsec;  HAL_I2C_Mem_Write(&hi2c1, 0x5A << 1, 0x0A, 1, &v, 1, 10);
    v = 1;     HAL_I2C_Mem_Write(&hi2c1, 0x5A << 1, 0x09, 1, &v, 1, 10);
}
```

Коэффициенты считает `tools/eq_coefs.py` (RBJ: PK, LS, HS, LP, HP или
импорт биквадов из REW), выводит последовательность регистров или массив
для C и печатает итоговую АЧХ:

```
python3 tools/eq_coefs.py --peq L:PK:42:-8:6 --peq R:PK:38:-10:8 \
                          --peq B:HP:18:0:0.707 --c > eq_table.h
python3 tools/eq_coefs.py --rew-l left.txt --rew-r right.txt --rew-negated --c
```

В REW фильтры рассчитывайте для 192 кГц (Equaliser: Generic, sample
rate 192000) — эквалайзер работает только на этой частоте, от частоты
входа ничего не зависит.

## Сборка в Gowin IDE

1. Устройство GW5A-LV25MG121NC1/I0, Verilog 2001 (Education-версия
   поддерживает этот чип).
2. Добавить `rtl/*.v`, констрейнты `gowin/ax_bridge_d2.cst` (прежний
   `ax_bridge.cst` из проекта убрать) и
   `gowin/ax_bridge.sdc`.
3. Таблицы коэффициентов (`coef/*.hex`) читаются при синтезе через
   `$readmemb` (файлы `coef/*.bin`, ширина строки ровно равна ширине памяти). Gowin IDE копирует исходники в свою папку проекта и
   относительный путь не находит: в `top.v` задайте полный путь в
   параметре `COEF_DIR`, прямыми слэшами и со слэшем в конце, например
   `parameter COEF_DIR = "C:/ax-bridge/coef/"`. Проверка: в логе синтеза
   не должно быть `Cannot open file`, иначе фильтры выкидываются
   оптимизатором (`swept`) и звука не будет.
4. Синтез → P&R → проверить положительный slack по `mclk_in` и `bclk_in`
   (обе 49.152 МГц) → прошить.

Ожидаемые ресурсы: 13 умножителей, 14 блоков памяти (крупнейший — ядро
ASRC 5121×50 бит), остальное — мелочь на фоне 23 040 LUT.
